// 01

Summary

Crocodile is the third machine of HackTheBox Starting Point Tier 1. It introduces the concept of chaining two services — combining information gathered from one misconfigured service to attack another. This mirrors how real-world attackers pivot between services during an engagement.

The target runs both FTP (port 21) and HTTP (port 80). The FTP server allows anonymous login and contains two files: a username list and a password list. Using these credentials against the web application's admin login panel grants access to the dashboard, where the flag is displayed.

The attack adds a new technique: directory brute-forcing with Gobuster to discover the hidden /login.php endpoint on the web server. This machine teaches that data found in one place can be a key to another.

Tool Reference

gobuster dir
gobuster dir -u <url> -w <wordlist>
Directory and file brute-forcer for discovering hidden web paths.
  • -u — target URL
  • -w — wordlist path
  • -x php,html — file extensions to try
  • -t 50 — concurrent threads
  • --status-codes 200,301 — filter codes
ftp (client)
ftp <host>
Standard FTP client. Anonymous login with username "anonymous" and empty/any password.
  • get <file> — download file
  • mget * — download all files
  • ls -la — list including hidden

Glossary

Directory Brute-Forcing
Directory brute-forcing (also called directory enumeration) is the technique of systematically requesting common file and folder names on a web server to discover hidden or unlisted content. Tools like Gobuster, Feroxbuster, and dirsearch automate this by sending hundreds of requests per second using wordlists. Common findings include admin panels (/admin, /login.php), backup files (/.bak), configuration files, and API endpoints. Effective web reconnaissance always includes directory brute-forcing.
Credential Leakage
Credential leakage occurs when authentication data (usernames, passwords, API keys, tokens) is exposed through unintended channels — such as public FTP shares, misconfigured S3 buckets, Git repositories, log files, or error messages. Even if the credentials appear "internal", any exposure on a network-accessible service must be treated as a critical vulnerability. The remediation is to audit what files are accessible to anonymous or low-privilege users on all public-facing services.
