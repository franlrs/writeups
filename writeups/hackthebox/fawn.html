// 01

Summary

Fawn is the second machine of the HackTheBox Starting Point Tier 0 track. It introduces the FTP (File Transfer Protocol) service and demonstrates the critical risk of leaving anonymous access enabled on a production FTP server.

The target runs vsftpd 3.0.3 on port 21 with anonymous login enabled — a configuration where any user can authenticate with the username anonymous and an arbitrary (or empty) password. This grants read access to the server's file system as exposed by the FTP daemon, where the flag file has been left in the root directory.

The exploitation requires no prior knowledge of valid credentials, no vulnerability in the software itself, and no exploit code — just the standard FTP client. The machine teaches the importance of auditing FTP server configurations before deploying them.

# Vulnerability Technique Impact
1 FTP Anonymous Login enabled FTP client with anonymous credentials Unauthenticated file system read access

// Key takeaway

Anonymous FTP access should be disabled by default unless explicitly required. If it must be enabled (e.g., for a public software mirror), the directory must be read-only, isolated, and must never contain sensitive files. Setting anonymous_enable=NO in /etc/vsftpd.conf eliminates this risk entirely.

// 02

Reconnaissance

1
Nmap service scan

We begin with an Nmap scan to identify open ports and running services. The -sV flag enables version detection, which is crucial here — knowing the exact FTP daemon helps determine whether anonymous access is likely configured.

RECON
$ nmap -sV -sC 10.129.x.x
PORT STATE SERVICE VERSION
21/tcp open ftp vsftpd 3.0.3
| ftp-anon: Anonymous FTP login allowed (FTP code 230)
|_-rw-r--r-- 1 0 0 32 Jun 04 2021 flag.txt
| ftp-syst:
| STAT:
| FTP server status:
| Connected to ::ffff:10.10.x.x
| Logged in as ftp
| TYPE: ASCII
|_END STATUS
Service Info: OS: Unix

Nmap's default scripts immediately reveal that Anonymous FTP login is allowed and that a file named flag.txt is present in the root FTP directory. The script even shows the file size (32 bytes) — enough for a typical CTF flag hash.

// Nmap NSE ftp-anon script

Nmap's ftp-anon script (included in -sC) automatically tests for anonymous FTP login and lists directory contents if successful. This is exactly the kind of misconfiguration audit that should be part of every initial scan.

// 03

Exploitation

1
Connect via FTP anonymous login

We connect to the FTP server using the standard ftp client. When prompted for a username, we enter anonymous. The password can be anything — by convention, your email address is used, but the server accepts any string or even an empty line.

EXPLOIT
$ ftp 10.129.x.x
Connected to 10.129.x.x.
220 (vsFTPd 3.0.3)
Name (10.129.x.x:kali): anonymous
331 Please specify the password.
Password: (press Enter or any string)
230 Login successful.
Remote system type is UNIX.
Using binary mode to transfer files.
ftp>
2
List files and download flag

Inside the FTP session, we use ls to confirm flag.txt is present, then get to download it to our local machine.

ftp> ls
229 Entering Extended Passive Mode (|||60738|)
150 Here comes the directory listing.
-rw-r--r-- 1 0 0 32 Jun 04 2021 flag.txt
226 Directory send OK.
ftp> get flag.txt
local: flag.txt remote: flag.txt
229 Entering Extended Passive Mode (|||18206|)
150 Opening BINARY mode data connection for flag.txt (32 bytes).
226 Transfer complete.
32 bytes received in 00:00 (0.53 KiB/s)

Tool Reference

ftp (client)
ftp <host>
Standard FTP command-line client for connecting, navigating and transferring files.
  • ls — list remote directory
  • get <file> — download file
  • mget *.txt — download multiple files
  • bye — close the session
nmap ftp-anon
nmap -sC <host>
NSE script that tests for anonymous FTP login and lists accessible files automatically.
  • -sC — run default scripts (includes ftp-anon)
  • -sV — detect service version
  • --script ftp-anon — run only ftp-anon

Glossary

FTP (File Transfer Protocol)
FTP is a standard network protocol (RFC 959) for transferring files between a client and server over TCP, using port 21 for control commands and a separate data port for file transfers. Like Telnet, it transmits everything including credentials in cleartext. It has been largely superseded by SFTP (SSH File Transfer Protocol) and FTPS (FTP over TLS), which add encryption. FTP operates in two modes: Active (server initiates data connection) and Passive (client initiates both connections, more firewall-friendly).
Anonymous FTP
Anonymous FTP allows unauthenticated access to an FTP server using the username anonymous (or ftp) and any string as password. Originally designed for public software distribution, it is a significant misconfiguration risk when enabled on servers that contain sensitive data. In vsftpd, it is controlled by the anonymous_enable directive in /etc/vsftpd.conf. Even when intentionally enabled, the anonymous user should be confined to a chroot jail with strict read-only permissions.
vsftpd (Very Secure FTP Daemon)
vsftpd is one of the most widely used FTP servers on Linux systems, included by default in many distributions. Despite its name ("very secure"), it can be dangerously misconfigured. Notably, vsftpd 2.3.4 contained a deliberately planted backdoor (CVE-2011-2523) that opened a root shell on port 6200 — a famous supply chain attack. Version 3.0.3 (used here) does not have this backdoor, but anonymous access remains a configuration risk when left enabled.
