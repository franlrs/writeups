// 01

Summary

TpRoot is an Easy difficulty machine from the DockerLabs platform. It runs on Linux Ubuntu and exposes two services: FTP (port 21) running vsftpd 2.3.4 and an HTTP (port 80) web server with Apache 2.4.58.

This machine is a classic case study on publicly known vulnerabilities and the critical importance of keeping software updated. The attack vector is completely direct: the FTP service runs vsftpd version 2.3.4, a version whose official source code was compromised in July 2011. A malicious actor injected a backdoor into the official source tree, making the server open a command shell on port 6200 upon receiving a specific string during the FTP login process.

Unlike other machines on the platform, there is no privilege escalation required here: the backdoor grants access as root directly. The full process — from deployment to flag — runs in under five minutes, making it an ideal machine to understand the cycle of reconnaissance → CVE identification → exploitation using community tools.

// Historical context — CVE-2011-2523

In July 2011, the official vsftpd repository at vsftpd.beasts.org was compromised. The attacker modified the source file sysdeputil.c so that upon receiving a username containing the string ":)" (smiley face), the server would spawn a root shell on port 6200/tcp. The backdoor was available publicly for less than 24 hours before being detected, but its impact was significant given that vsftpd was one of the most widely deployed FTP servers on Linux systems at the time. This incident is one of the earliest documented software supply chain attacks.

// 02

Reconnaissance

1
Deploy the machine

The first step is to deploy the vulnerable container. DockerLabs provides the auto_deploy.sh script which builds the image from the tproot.tar archive, automatically assigns an IP within the Docker internal network (172.17.0.x), and keeps the container running until Ctrl+C is pressed. sudo is required because Docker needs elevated privileges to manage network interfaces.

DEPLOY
$ sudo bash auto_deploy.sh tproot.tar
Deploying vulnerable machine, please wait.
 
Machine deployed, its IP address is ——> 172.17.0.2
Press Ctrl+C when done to remove the machine
2
Connectivity check — ping TTL

With the container deployed, we verify connectivity by sending 3 ICMP packets with the -c 3 flag. Beyond confirming the host is alive, the TTL field in the response lets us infer the operating system without any additional tooling: a TTL=64 indicates Linux (Windows returns 128, Cisco IOS returns 255). In Docker networks with no intermediate routers, the received TTL is identical to the host's original TTL, making the identification direct and reliable.

PING
$ ping 172.17.0.2 -c 3
PING 172.17.0.2 (172.17.0.2) 56(84) bytes of data.
64 bytes from 172.17.0.2: icmp_seq=1 ttl=64 time=0.140 ms
64 bytes from 172.17.0.2: icmp_seq=2 ttl=64 time=0.071 ms
64 bytes from 172.17.0.2: icmp_seq=3 ttl=64 time=0.060 ms
 
--- 172.17.0.2 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss
3
Full port scan — Nmap

With connectivity confirmed, we launch an exhaustive scan with Nmap. The -p- flag scans all 65,535 TCP ports. -sSCV combines stealth SYN scan (-sS), service version detection (-sV), and default NSE scripts (-sC) which perform automatic checks such as anonymous FTP login attempts. -n disables DNS resolution, -Pn skips host discovery, and --min-rate=5000 sets a minimum packet rate for fast completion. Output is exported to XML for later reporting.

NMAP
$ sudo nmap -p- -sSCV -n -Pn --min-rate=5000 --open 172.17.0.2 -oX tproot.xml

// Critical finding

The scan reveals vsftpd 2.3.4 on port 21. This specific version is notoriously vulnerable: it was the version infected with a backdoor in 2011 and is catalogued in multiple vulnerability databases as trivially exploitable. Its presence on an exposed system is an immediate red flag that must be investigated as first priority.

4
Generate HTML report — xsltproc

The tproot.xml file generated by Nmap can be transformed into an interactive HTML report using xsltproc with the stylesheet Nmap includes in its installation. This produces a tabular view of all discovered hosts, ports, and services, making results easy to review and include in security reports. In the report, port 21 shows vsftpd 2.3.4 highlighted as a potentially vulnerable version.

XSLTPROC
$ xsltproc tproot.xml -o tproot_report.html

// 03

Exploitation

5
Search for the exploit — Searchsploit

With vsftpd 2.3.4 identified, the next step is to verify whether a public exploit exists for it. Searchsploit is the CLI interface for Exploit-DB, a vulnerability database maintained by Offensive Security. Searching by name and version yields two results: a pure Python exploit (49757.py) and its Metasploit version. We will use the manual Python script to understand the exploit's mechanics without relying on external frameworks.

SEARCHSPLOIT
$ searchsploit vsftpd 2.3.4
Exploit Title | Path
--------------------------------------------------------|-----------------------
vsftpd 2.3.4 - Backdoor Command Execution | unix/remote/49757.py
vsftpd 2.3.4 - Backdoor Command Execution (Metasploit) | unix/remote/17491.rb
 
Shellcodes: No Results
6
Retrieve the exploit — searchsploit -m

The -m flag of searchsploit (mirror) copies the exploit file directly to the current working directory. The output confirms the exploit path, file type, its Exploit-DB URL, and the associated CVE code. The Verified: True field indicates the exploit has been tested and confirmed functional by the Exploit-DB team, which increases confidence in a successful exploitation.

MIRROR EXPLOIT
$ searchsploit -m 49757.py
Exploit: vsftpd 2.3.4 - Backdoor Command Execution
URL: https://www.exploit-db.com/exploits/49757
Path: /usr/share/exploitdb/exploits/unix/remote/49757.py
Codes: CVE-2011-2523
Verified: True
File Type: Python script, ASCII text executable
Copied to: /home/kali/tproot/49757.py
7
Execute the exploit — root access

We execute the Python script providing only the target IP as an argument. The exploit works in two phases: first it opens a connection to port 21/tcp and sends a username containing the sequence :) (the backdoor trigger), which causes the vsftpd server to spawn a root shell on port 6200/tcp. Immediately after, the script connects to that port and delivers an interactive shell already running as root.

If the first execution does not respond, simply run the script a second time — port 6200 may need a moment to open. Once inside, we stabilise the TTY with script /dev/null -c bash to get a fully functional bash session with Ctrl+C support and command history.

EXPLOIT
$ python3 49757.py 172.17.0.2
Success, shell opened
Send `exit` to quit
 
whoami
root

// Note — exploit reliability

If the script hangs or returns no output on the first run, execute it a second time. The backdoor on port 6200 may take 1–2 seconds to become available after the FTP trigger is sent. A second attempt is almost always sufficient.

// 04

Post-Exploitation

8
TTY stabilisation

The shell obtained through the backdoor is a dumb shell without a full TTY. Ctrl+C kills the session instead of interrupting the current process, and interactive tools like vim will not function correctly. We stabilise it using script /dev/null -c bash, which creates a proper pseudo-TTY:

TTY
$ script /dev/null -c bash
9
Verify access and retrieve flag
VERIFY
root@tproot:~# whoami && id && ls /root
root
uid=0(root) gid=0(root) groups=0(root)
 
root.txt
FLAG
root@tproot:~# cat /root/root.txt
c0ngr4ts_y0u_0wn3d_tpr00t!

// Lessons learned

TpRoot demonstrates the danger of running end-of-life software in production. vsftpd 2.3.4 is more than a decade old and its vulnerability has been public knowledge since 2011. A single apt upgrade would have completely prevented this compromise. Always keep your services updated and regularly audit installed versions against known CVE databases.

Command Reference

nmap
nmap -p- -sSCV -n -Pn --min-rate=5000 --open <IP> -oX out.xml
Network and port scanner. Discovers active services, their versions, and runs NSE enumeration scripts on each open port.
  • -p- — Scans all 65,535 TCP ports
  • -sS — Stealth SYN scan (no full handshake)
  • -sC — Default NSE scripts
  • -sV — Service version detection
  • -n — No DNS resolution (faster)
  • -Pn — Skip host discovery
  • --min-rate — Minimum packets per second
  • --open — Show only open ports
  • -oX — Export results to XML
searchsploit
searchsploit <service> <version>
CLI interface for Exploit-DB. Searches for known exploits by software name, version, or CVE, and copies scripts to the working directory.
  • -m <path> — Mirror (copy) exploit to current directory
  • -u — Update local exploit database
  • -t — Search only in exploit title
  • -w — Show Exploit-DB URL instead of local path
  • --id — Show Exploit-DB ID alongside name
python3 49757.py
python3 49757.py <target_IP>
Exploit for CVE-2011-2523. Opens an FTP connection to port 21, activates the backdoor by sending ":)" in the username, and connects to port 6200 where vsftpd opens a root shell.
  • Single argument: target IP or hostname
  • Connects to port 21/tcp (FTP)
  • Activates backdoor with username user:)
  • Receives shell on 6200/tcp
  • Run twice if first attempt does not respond
script /dev/null -c bash
script /dev/null -c bash
TTY stabilisation technique. Replaces the basic backdoor shell with a fully interactive bash session supporting Ctrl+C, command history, and ANSI colours.
  • /dev/null — Discards the session log
  • -c bash — Runs bash inside the script session
  • Enables Ctrl+C without killing the connection
  • Required for interactive tools (vim, sudo, etc.)
  • Alternative: python3 -c 'import pty; pty.spawn("/bin/bash")'
xsltproc
xsltproc <file.xml> -o <report.html>
XSLT command-line processor. Transforms Nmap XML output into a navigable HTML report using the stylesheet bundled with Nmap.
  • Requires the XML file generated by nmap -oX
  • -o — Output HTML filename
  • Nmap stylesheet is in /usr/share/nmap/
  • Useful for pentest documentation and reports
ping
ping <IP> -c <n>
ICMP connectivity tool. Confirms the host is alive and provides passive OS fingerprinting via the TTL field in the response.
  • -c <n> — Limit to n packets
  • -i <seconds> — Interval between packets
  • TTL ≈ 64 → Linux/Unix
  • TTL ≈ 128 → Windows
  • TTL ≈ 255 → Cisco IOS / Solaris

Glossary

vsftpd — Very Secure FTP Daemon
vsftpd (Very Secure FTP Daemon) is one of the most widely used FTP servers on Linux/Unix systems, originally designed with a strong focus on security, performance, and stability. Version 2.3.4 was compromised in July 2011 when an unknown attacker modified the source code in the project's official repository, inserting a backdoor that activates a root shell upon receiving the character ":)" in the username field during FTP login. It was detected and removed from the repository in under 24 hours, but infected copies continued to circulate and were deployed on unpatched systems. This incident remains one of the most cited examples of a software supply chain attack.
CVE — Common Vulnerabilities and Exposures
The CVE system is an international standard for the unique identification of security vulnerabilities in software and hardware. Each entry receives a unique identifier with the format CVE-YEAR-NUMBER. CVE-2011-2523 corresponds to the vsftpd 2.3.4 backdoor: the year 2011 indicates when it was discovered and reported, and 2523 is the sequential index assigned. The CVE system is maintained by MITRE Corporation. Databases such as NVD (National Vulnerability Database) and Exploit-DB index these vulnerabilities alongside risk scores (CVSS), available patches, and known exploits.
Backdoor
A backdoor is any method that allows unauthorised access to a system, application, or network, generally bypassing normal authentication controls. In the vsftpd 2.3.4 context, the backdoor is of the hardcoded trigger type: the malicious code is embedded in the compiled server binary and is activated by a specific condition (username containing ":)"), requiring no credentials. Types of backdoors include: compiler backdoors (injected in the toolchain), repository backdoors (this case), package backdoors (in dependency managers), and configuration backdoors (hidden accounts, open ports). Detection requires source code analysis, binary auditing, or network traffic monitoring.
FTP — File Transfer Protocol
FTP (File Transfer Protocol, RFC 959) is a standard network protocol for file transfer between systems. It operates on two channels: the control channel (port 21/tcp) for commands and the data channel (port 20/tcp active, or a negotiated port in passive mode) for actual file transfer. FTP transmits credentials and data as plaintext without encryption, making it inherently insecure on untrusted networks. Secure alternatives are SFTP (FTP over SSH, port 22) and FTPS (FTP over TLS/SSL). The anonymous mode error "OOPS: cannot change directory" observed in the scan indicates anonymous FTP is enabled but misconfigured, though this does not affect exploitation of the backdoor.
Supply Chain Attack
A software supply chain attack targets less-secure elements in the software distribution chain rather than the final target directly. This includes compromising the official source code repository (as in vsftpd 2.3.4), injecting malicious code into third-party dependencies (npm, PyPI, RubyGems), attacking the build process (trojanised compilers), or compromising update distribution servers. The vsftpd 2.3.4 incident (2011) was one of the first widely documented cases, but the vector was popularised by later incidents such as SolarWinds Orion (2020) and the XZ Utils backdoor (2024, CVE-2024-3094). Defences include: cryptographic signature verification of packages, reproducible builds, and dependency integrity monitoring.
TTL — Time To Live and OS Fingerprinting
TTL (Time To Live) is an 8-bit field in the IP header that indicates how many router hops a packet can traverse before being discarded. Each router decrements the TTL by 1; when it reaches 0 the packet is dropped and an ICMP "Time Exceeded" message is sent to the source. Different operating systems have different initial TTL values: Linux/Unix → 64, Windows → 128, Solaris/AIX → 254, Cisco IOS → 255. In Docker networks without intermediate routing, the received TTL equals the initial TTL, enabling direct OS identification. This passive fingerprinting technique generates no alerts as it simply reads a standard field from any network response.
